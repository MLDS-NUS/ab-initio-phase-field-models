# figures/

Each figure the paper draws with matplotlib is a directory `figures/<dir>/` holding `figdata/` (the arrays the figure shows, nothing computed at draw time) and `draw.py` (reads `figdata/`, draws, saves). `figures/reference/` holds the paper's files, which the drawings are compared with at 200 dpi. Extended Data Fig. 1 and Supplementary Fig. S1 also ship their painted 3-D boxes pre-rendered in `figdata/` (`painted_*.png`, RGBA layers at 600 dpi, the resolution of the PNGs they appear in), which `draw.py` composites under the box edges and labels it still draws, so every figure draws in seconds; with `AIPF_FIGURES_RENDER_3D=1` (or `true`, `yes`) in its environment, `draw.py` paints the boxes from the fields again (minutes) and rewrites those layers before compositing them. Each layer stores a digest of the arrays it was painted from and the layout of its box, and refuses to draw, naming the command that repaints it, when either has changed. The test drops the variable, so it never repaints.

Build: "conda" is matplotlib 3.10.8 with freetype 2.14.1 from conda-forge (`figures/common/BUILD.txt`), which `env/environment.yml` installs into the aipf environment together with PyMuPDF (it rasterises the PDFs for the test and the notebook) and nbconvert and ipykernel (they run the notebook). "pip wheel" is the pip wheel of matplotlib 3.10.8, which bundles freetype 2.6.1 (named by `BUILD` in that `draw.py`). It is kept outside the environment, in `tools/matplotlib-3.10.8-wheel` under the data farm (`data/` by default), and `python figures/common/wheel.py` installs it there. It needs the network, and its sha256 pins the CPython 3.12 wheel for x86-64 Linux, so pip refuses it on another interpreter or platform. The test and the notebook put it first on the path of the process that draws the coarsening rows and stop with that command when it is missing. Freetype places glyphs differently in the two builds, so a figure is pixel-identical only under its own build.

**Tests.** `pytest tests/test_figures.py` checks that every `draw.py` keeps the contract (one-line docstring, `draw`, the reference files it maps onto, a cause for every bound). `pytest tests/test_figures.py -m slow` draws each figure in a process of its own under its build (`figures/common/render.py`, with the pip wheel first on that process's path where the figure asks for it) and compares every file with `figures/reference/` at 200 dpi. It fails with the install command when the pip wheel is missing. Where the site declares no latexmk (`AIPF_LATEXMK`, or `latexmk` under `[site]` in `aipf.toml`), the assembled Fig. 5 is a skipped test case that names that fact, and its panels are still compared. The whole slow set takes under a minute. `pytest tests/test_figdata_from_package.py -m slow` recomputes with the package the figure data that comes from the published models (the phase diagrams of Fig. 3a, the Γ maps of Fig. 4, the domes and isopleth of Fig. 5 at 400 and 800 GPa, the free energies of mixing and Γ of Extended Data Figs. 3 and 5, and the free energy of Extended Data Fig. 6) and holds it to the committed figdata within stated bounds.

**Notebook.** `figures/paper_figures.ipynb` draws every figure above, in the order of the paper (main text, Extended Data, Supplementary), into `figures/out/<dir>/` (gitignored) and shows each file it writes. Each cell runs the same `render.py` as the test, so every figure is drawn under its own build while the kernel runs in the aipf environment, and it was executed there. Open it in that environment and run all cells, or run it headless with `jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=-1 figures/paper_figures.ipynb`. A full run takes about a minute.
